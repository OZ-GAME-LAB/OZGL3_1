Project M — 튜토리얼·1스테이지 도시 아트 키트 사용안내
작성일: 2026-10-19
기준 환경: Unity 6000.3.21f1 / Universal Render Pipeline 17.3.0
아래 파일 경로는 프로젝트 루트 기준입니다.

사이드뷰 개정 기준
전체 진행 축은 X, 높이는 Y이며 플레이어의 물리 이동은 Z를 고정합니다. 카메라는 -Z 쪽에서 횡스크롤을 보되 약한 수평·수직 각도로 지붕과 소품의 두께를 보여 주는 2.5D 구성을 사용합니다. 이동·전투·상호작용 모션과 소품 배치는 이 게임 축을 기준으로 검수합니다.

1. 먼저 열어 볼 씬
Assets/Art/Stage01Kit/UrbanKit_Preview.unity

Unity에서 이 씬을 열면 도시 블록과 주인공을 함께 확인할 수 있습니다. 튜토리얼 블록과 1스테이지 블록을 나란히 배치한 별도 프리뷰입니다. 원본 MainScene은 변경하지 않았습니다.
실행 조작 확인은 아래 키를 사용합니다. 프리뷰 키는 UrbanKitPreviewControls가 담당하며 일반 플레이어 프리팹에 포함하지 않습니다.

마시기·던지기·상호작용·줍기는 지면에 서서 멈춘 상태에서 요청하세요. 이동·점프·피격·대시 등으로 동작이 취소될 수 있습니다. 5번은 확인용 물약을 카메라에 가까운 손에 보여 줍니다. 6번은 같은 손에 든 물약을 투척 시점에 놓고 진행 방향의 포물선 경로로 날려 보냅니다. 이는 프리뷰용 시각 투척으로, 아이템 소비·적 타격·폭발·상태이상 효과는 실행하지 않습니다.
기본 이동 속도는 5m/s, Ctrl 걷기는 2.2m/s입니다. Walk/Run의 발 구름 재생 속도도 이 실제 이동 속도에 맞추며 이동 거리는 기존 Rigidbody 컨트롤러가 담당합니다.
F1/F2/F3은 아트 확인용 자유 장착입니다. 튜토리얼 후 무기 1회 구매·자동 장착·다른 무기 구매 차단이라는 게임 규칙은 이 프리뷰 입력에 연결되어 있지 않습니다.

4. 메시·재질·LOD
환경·소품·무기는 정리된 메시의 버텍스 컬러를 공용 URP 재질 하나로 표시합니다.
재질: Assets/Art/Stage01Kit/Materials/Urban_SharedPalette.mat
셰이더: Assets/Art/Stage01Kit/Materials/Urban_VertexColor.shader

환경은 어두운 청회색 콘크리트·금속과 저채도 식생으로 우중충한 도시 분위기를 구성합니다. 보행면과 옥상 테두리는 밝기 차를 남겨 경로를 구별할 수 있게 합니다. 일부 창문·가로등·자판기와 게이트 중심·지팡이 수정에만 작은 발광 포인트를 사용합니다. 발광은 버텍스 컬러로 같은 불투명 셰이더에서 처리하므로 별도 투명 패스나 발광 전용 재질을 늘리지 않습니다. 환경광·주광·그림자는 실제 씬 조명을 반영합니다.

건물 4종은 각각 LOD0/LOD1을 갖고 LODGroup이 거리에 따라 전환합니다. 한 시점에 하나의 LOD가 표시됩니다. 검증 보고서의 건물 triangles 값은 두 LOD 메시의 합이므로, 그 수치가 매 프레임 동시에 그려지는 삼각형 수라는 뜻은 아닙니다.
공유 재질·LOD·단순 충돌은 성능을 고려한 구성입니다. GTX 1650 개발 PC 또는 최종 출시 기기에서의 프레임 성능을 보장하는 측정 결과는 아닙니다.
레벨 수정본은 별도 씬이나 Prefab Variant에서 관리하세요. 재생성 메뉴는 생성된 메시·재질·프리팹·프리뷰 씬을 갱신합니다.

5. 무기 장착 API
파일: Assets/Art/Stage01Kit/HandSocketEquipment.cs
파일: Assets/Art/Stage01Kit/SocketWeapon.cs

플레이어 루트의 HandSocketEquipment에 SocketWeapon 프리팹 컴포넌트를 넘깁니다.

    HandSocketEquipment equipment = player.GetComponent<HandSocketEquipment>();
    SocketWeapon sword = swordPrefab.GetComponent<SocketWeapon>();
    bool equipped = equipment.Equip(sword);

Equip은 성공 여부를 bool로 반환합니다. SocketWeapon의 그립 위치·회전을 가까운 손 소켓에 적용하며 왼손에는 반사된 그립을 사용합니다. NearHandSocket 또는 GetNearHandSocket()으로 현재 소켓을 얻고 UsesLeftHand로 왼손 여부를 확인할 수 있습니다. 위치를 조정할 때 캐릭터 손 뼈를 임의로 바꾸기보다 무기 프리팹의 그립 설정을 조정하세요.
장착 시 Animator Override Controller가 공통 기본 공격 Punch를 검의 SwordSlash 또는 지팡이의 MagicCast로 교체합니다. Unequip()은 무기를 제거하고 맨손 컨트롤러와 주먹 재생 속도 설정을 복원합니다.
FacingLeft Animator bool은 진행 방향에 맞춰 상태의 Humanoid 미러링을 전환합니다. 포션과 무기도 같은 방향 규칙을 사용합니다. 섭취·투척·상호작용·줍기 동안에는 무기를 잠시 숨겨 손의 소품과 겹치지 않게 하고, 사망 상태에서도 무기를 숨깁니다.
이 API는 장착 모델과 모션을 처리합니다. 실제 검 공격 판정, 마력탄 발사, 스킬 계열 제한, 가격·구매 포인트·1회 구매 확정·저장은 구매/전투 코드의 책임입니다. 지팡이를 들었다고 기존 주먹 판정이 자동으로 원거리 마법 판정으로 바뀌지는 않습니다.

6. 추가 동작 API와 콜백
파일: Assets/1.Script/Player/ProtagonistActionAnimator.cs

추가한 6개 동작:
Drink(마시기), Throw(던지기), SwordSlash(검 베기), MagicCast(마법 시전), Interact(상호작용), Pickup(줍기)
기존 이동·주먹·점프와 피격·사망·대시·착지 애니메이션도 함께 사용합니다.
점프는 상승·정점·하강 포즈와 착지 상태를 나눠 실제 수직 속도에 맞춰 표시합니다.

공통 호출:
    bool started = actions.TryPlay(action, onCommit, onCompleted, duration);

예를 들어 Drink는 다음처럼 요청할 수 있습니다. 아래 주석 부분에 실제 인벤토리 코드를 연결하세요.

    ProtagonistActionAnimator actions = player.GetComponent<ProtagonistActionAnimator>();
    bool started = actions.TryDrink(
        consume: () => { /* 수량·사용 조건 재확인 후 소비와 효과 적용 */ },
        completed: () => { /* 정상 종료 후 표시 정리 */ });

간편 호출: TryDrink / TryThrow / TryInteract / TryPickup
검 베기·마법 시전 직접 요청: TryPlay(ProtagonistExtraAction.SwordSlash, ...) 또는 MagicCast
duration을 생략하거나 음수로 두면 프리팹에 설정된 기본 재생 시간을 사용합니다.

started=true는 요청 수락을 뜻합니다. 실제 완료를 뜻하지 않습니다.
onCommit은 설정된 동작 진행 지점에 도달했을 때 1회 호출됩니다. 아이템 소비·투사체 생성·실제 상호작용 등은 호출자가 이 콜백에 연결합니다. TryPlay 시점과 onCommit 시점에 같은 처리를 중복 실행하지 마세요.
물약은 ConsumableHandProp.AttachTo(equipment.NearHandSocket, equipment.UsesLeftHand)로 장착합니다. 투척용 손잡이는 AttachForThrow(socket, mirrored)를 사용합니다. UrbanConsumableBuilder는 실제 루트 Mecanim 컨트롤러의 Drink 상태를 평가해 병 몸통 중심을 손에 두고 입구를 입 쪽으로 맞춘 고정 위치·회전을 계산합니다. 왼쪽 진행의 실제 미러 포즈에서도 반사된 위치·회전의 접촉 오차를 확인합니다. Drink의 최종 소비 시점은 이 보정값으로 갱신되며 ArtSources/Stage01Kit/consumable-grip.json에 기록됩니다. 소모 처리를 호출해도 시각용 병은 동작 완료나 취소까지 유지할 수 있습니다.
onCompleted는 정상 완료 때 호출됩니다. 취소 때 정리가 필요하면 Cancelled 이벤트에 연결하고, 필요에 따라 Cancel()로 취소할 수 있습니다. 이미 onCommit에서 적용한 게임 효과는 이후 취소해도 이 컴포넌트가 되돌리지 않습니다.
물약 수량·대상 유효성·스킬 사용 가능 여부·대상 중복 처리·저장 데이터는 호출자가 관리합니다. 모션 프리팹에는 게임 효과를 직접 실행하는 가져온 Animation Event를 넣지 않았습니다.

기본 공격은 입력 즉시 판정을 실행하지 않고 ProtagonistAnimationDriver와 무기에 설정된 공격 접촉 지점까지 기다렸다가 IPlayerAttack.Execute를 한 번 호출합니다. 접촉 전에 피격·사망 등으로 공격 상태를 벗어나면 예약 판정은 실행되지 않습니다. 접촉 후 이미 적용된 피해는 취소로 되돌리지 않습니다. 공격력·피해 계수·히트박스 자체는 기존 전투 구현을 사용합니다.
접촉 지점은 실제 Mecanim 포즈의 손·무기 끝 이동을 측정해 맨손 0.82, 검 0.78, 지팡이 0.73으로 맞췄습니다. 검은 원본 연속 베기에서 첫 베기와 회수만 사용해 짧은 기본 공격에서 두 번 베기가 지나치게 압축되지 않게 했습니다. 측정 원본은 SideviewReview/contact-diagnostics.json에 기록합니다.

런타임 시각 접지
파일: Assets/Art/Characters/Protagonist01/Runtime/ProtagonistVisualGrounding.cs
리타깃으로 발이 지면 안에 들어가거나 뜨는 문제는 적은 수의 스킨 표본으로 보정합니다. 지상 동작은 발바닥 표본, 사망은 전신 표본의 최저점을 사용해 시각 브랜치만 위아래로 맞춥니다. 공중에서는 높이 보정을 해제하며 Dash/Hit의 기존 방향 오차도 시각 브랜치에서 보정합니다. 매 프레임 전체 메시 BakeMesh를 호출하지 않고 물리 루트·콜라이더·점프 궤적·판정 위치는 바꾸지 않습니다. 손 소켓과 장착 소품도 같은 브랜치를 따라 움직입니다.
ProtagonistHandGrip과 ProtagonistVisualGrounding은 중첩 Visual에서 중복 실행되지 않도록 구성합니다. 수동 포즈 캡처 시에는 Grounding.ResetPreview() → Animator.Play/Update → HandGrip.ApplyPreview() → Grounding.ApplyPreview(grounded, dead) 순서를 사용합니다.

7. 다시 생성하기
Unity 메뉴: Tools > Project M > Build Tutorial and Stage 1 Art Kit
호출 메서드: UrbanKitSetup.Build()

저장 확인 후 실행하면 로컬에 있는 원본 모델과 생성 코드를 이용해 키트, 추가 동작 설정, 블록, 장착 플레이어, 프리뷰 씬을 다시 만듭니다. 이 메뉴 자체가 Meshy 모델을 새로 요청하지는 않습니다.
이번 도시 키트·추가 모션 생성에 사용한 Meshy 크레딧은 실제 총 63입니다. 모델 9개 45크레딧 + 추가 동작 6개 18크레딧입니다. 도시 모듈 16종과 물약 변형 4종은 로컬 제작이며 추가 생성 크레딧을 사용하지 않았습니다.
이번 사이드뷰 검수·수정 개정에는 새 Meshy 크레딧을 사용하지 않았습니다. 기존 생성물의 메시 분리·팔레트·그립·임포트·재생 속도·런타임 표시를 로컬에서 수정합니다.
