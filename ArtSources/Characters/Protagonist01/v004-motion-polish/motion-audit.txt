판정 요약
현재 어색함은 단순히 저폴리 모델이나 적은 애니메이션 FPS 하나로 설명되지 않는다. 긴 사람형 액션의 일부분을 큰 배율로 압축하고, 회복 동작을 중간에서 잘라 Idle로 보내며, 짧은 공중/대시 포즈를 길게 고정하고, 발바닥 오차를 캐릭터 전체 Y 보정으로 가리는 요소가 겹친다. 발이 땅을 뚫지 않는 검사를 통과했다는 사실과 자연스러운 모션이라는 판정은 별개다.
새 v004는 원본 복제본에서 자세/지지발/회복 구간을 다듬어야 한다. 기존 모션의 재생속도와 마지막 프레임만 다시 바꾸는 것으로 전체 문제를 해결했다고 판단하면 안 된다.

1. 원본 리그, 실제 샘플 수와 FPS
기존 Rig/Walk/Run/Actions/ExtendedActions는 모두 24개의 LimbNode/Root/Skeleton 모델을 갖는다. 손가락 관절은 없다. LeftHand/RightHand 아래에 손가락을 개별 굽히는 골격이 없으므로 MCP/PIP/DIP나 엄지 반대맞섬을 기존 animation muscle로 복구할 수 없다.
기존 source FBX의 가장 흔한 양의 KeyTime 간격은 약 1/30초다. Walk는 각 curve 32 keys/1.0333초, Run은 20 keys/0.6333초다. 원본 자체가 7~9 FPS 모션인 것은 아니다. Unity import는 animationCompression=0, resampleCurves=0으로 추가적인 compression/key-reduction을 사용하지 않는다.
기존 검수 GIF는 16 FPS다. Walk 한 사이클이 9개 프레임, Run은 7개 프레임, 0.3초 기본 공격은 실제 active 구간 약 5개 프레임이다. 그림이 건너뛰는 정도를 GIF만으로 모두 런타임 결함이라고 판정하면 안 된다. 다만 GIF/PNG에서 확인되는 고정 포즈·회복 생략·대규모 자세 변화는 60 FPS로 보아도 사라지지 않는다.
v004 샘플은 최소 30 FPS PNG sequence로 검수하고, 클립 데이터 측정은 60/120 Hz로 따로 수행한다. GIF에는 명시한 재생률을 적용하고, 최종/첫 중복 프레임을 루프에 두 번 넣지 않는다. 60 Hz resample은 관절의 새 움직임을 만들어 주지 않으므로 source pose 품질 개선과 구분해야 한다.

3. loop와 root 처리
Walk/Run은 loopTime/loopBlend가 켜져 있으며, 이전 120-sample 진단에서 끝과 시작의 손/발 위치는 거의 일치했다. C0 위치 일치가 C1 속도 일치를 뜻하지는 않는다. 이 진단의 양 끝 one-sided foot velocity 차이는 Walk 약 0.24/0.34m/s, Run 약 2.06/0.77m/s였다. 이는 경계 속도 이상을 재검수할 근거이지, 짧은 one-sided derivative만으로 source loop가 반드시 잘못됐다고 확정하는 수치는 아니다. 정확한 한 주기를 찾고 wraparound 중앙차분/수 프레임 구간 피팅으로 다시 측정해야 한다.
기존 Import의 lockRootPositionXZ=true는 이동을 pose 쪽에 굽는 설정이다. 원본에 travel이 있으면 applyRootMotion=false만으로 완전한 제자리 클립이 된다고 가정할 수 없다. 새 v004 source의 root/body/hips travel을 각각 측정하고, nominal root trajectory를 빼서 in-place pose를 만들지, trajectory를 별도 데이터로 보존할지 결정해야 한다. 전체 캐릭터의 authored local bob까지 0으로 만들면 상체가 경직된다.
기존 extra actions는 keepOriginalOrientation=false/lockRootRotation=false로 source의 약 +57도 또는 -24도 방향 오차를 크게 줄였다. 새 source도 root yaw만 검사하지 말고 hips/chest/hand sweep의 실제 +X 진행축과 ±X 방향을 함께 검사한다. 공격을 읽기 쉽게 하려다가 torso 모든 yaw를 0으로 만들면 체중 이동과 counter-rotation이 사라진다.
상체·무기·시선은 약한 깊이감의 side view에서 확인한다. 완전 정면이나 높은 3/4 뷰만으로 통과시키지 않는다.

4. grounding이 가린 근본 문제
현행 ProtagonistVisualGrounding은 grounded 동안 선택된 sole marker의 world minimum을 capsule bottom에 맞추기 위해 visualRoot 전체를 매 프레임 올리거나 내린다. support foot의 heel/toe contact나 stance/flight phase를 판단하지 않는다. 양발이 잠깐 뜨는 달리기 포즈도 physics capsule이 grounded이면 전체 모델을 내려 최저 발을 바닥에 고정한다.
실제 16 FPS 캡처의 visualGroundOffset 범위와 인접 프레임 변화:
Idle: +3.57~3.99cm, 최대 변화 0.07cm.
Walk: -2.34~+6.02cm, 최대 변화 6.75cm.
Run: -4.98~+4.49cm, 최대 변화 9.48cm.
Land: +3.84~18.85cm, 최대 변화 14.96cm.
Jump 착지: 공중 0에서 +18.43cm로 전환.
Dash: +3.85~14.44cm, 최대 변화 10.59cm.
마지막 캡처에서 sole clearance가 거의 2mm로 유지되는 것은 이 보정의 결과이며, 원본에 자연스러운 지지발/힙 경로가 있다는 뜻은 아니다.
Grounding.Update의 base reset → Mecanim → HandGrip.LateUpdate(90) → Grounding.LateUpdate(110) 순서는 누적 피드백을 막기 위한 구조로는 일관된다. 하지만 support 선택 없이 global minimum에 끌어당기는 방식 자체가 자세/높이 변화와 foot switching snap을 만든다.
v004 독립 샘플은 이 runtime global floor snap을 사용하지 않은 원형과 보정형을 비교한다. 지지발은 stance 중만 world-space anchor에 두고 heel/toe roll을 살린다. hips 보정은 body balance와 관절길이 안에서 제한하고 시간 연속성을 유지한다. run flight와 jump pose는 지지발 없음 상태로 둔다. 이번 작업에서 기존 grounding/gameplay 코드를 바꾸지 않는다.

5. 모션별 정밀 판정과 개선 방향

Idle / Idle_Fists
PNG #0/#9/#18/#27/#36/#45/#54/#63에서 몸이 측면→등/정면→측면으로 크게 돌아간다. 조용한 기본 대기라기보다 look-around variation이다. 발도 고정된 안정 stance에서 벗어나 몸 전체를 바꾸며, 연속 공격/걷기 입출구가 매번 다르게 보인다.
새 기본 Idle는 발 간격과 root heading을 일정하게 두고 작은 호흡·흉곽/골반 counter motion·시선만 남긴다. look-around는 필요하면 별도 Idle_LookAround로 분리한다. 앞뒤 동일 pose/velocity인 2~4초 루프를 권장한다.

Walk / Walk_Fists
실제 프레임에서 팔이 비교적 곧게 내려와 손이 골반 옆에서 작은 왕복만 하고, 빠른 다리 cadence와 결합해 경직돼 보인다. heel strike→flat support→toe-off가 whole-visual Y 보정에 섞여 있다. 발이 땅을 뚫지 않는 것만으로 합격시키지 않는다.
새 clip는 팔꿈치의 부드러운 굽힘, 어깨-골반 phase offset, heel/toe roll, 짧은 양발 support를 작성한다. nominal speed에서 support 발의 수평 drift와 pelvis의 좌우/수직 이동을 함께 측정한다. 무기 그립용 팔 자세를 걷기에 억지로 복사하지 않는다.

Run / Run_Fists
원본 한 cycle 0.633초가 0.421초로 가속되어 GIF에 7개 포즈만 남는다. whole-model sole snap이 자연 flight를 제거하고 9.48cm 높이 변경을 만들며, 이 상태에서 늘어난 cadence가 더 기계적으로 보인다.
새 clip는 lean·knee drive·heel recovery·arm bend를 일관되게 만들고, 실제 flight와 짧은 support를 유지한다. 원본 걷기 동작을 단순 가속한 변형으로 만들지 않는다. nominal speed/stride/cadence를 보고서에 함께 적는다.

Punch / Punch_Right_Jab
현행은 source 0~.62만 남겼는데 그 구간에서 실제 최대 신전이 normalized .84 부근이다. .3초 기준 접촉까지 약 .25초, 남은 회복 시간은 약 .05초다. PNG #7/#9 후 #10에서 Idle로 급히 돌아가 guard→strike→retract가 잘 분리되지 않는다. 3.58배 균일 가속은 손이 나오기 전 지연과 마지막 회복 부족을 동시에 만든다.
새 clip는 준비·빠른 신전·짧은 정점·주먹 회수를 완결한 단일 jab로 구성한다. 준비 여백을 삭제한 뒤 전체를 재가속하는 것과 phase별 재저작을 구분한다. 팔꿈치를 끝까지 잠그지 않고 어깨/골반 counter-rotation 및 반대 손 guard를 둔다. 0.3초 대응이 필요하면 해당 길이 안에 anticipation/active/recovery를 모두 새로 배치한다. 접촉 marker는 새 clip 실측 후 결정하며 옛 .82를 무조건 복사하지 않는다.

JumpTakeoff / Jump_Full
기존 JumpTakeoff는 Regular_Jump 0~.25를 .16초에 재생한다. 전체 비행은 jumpForce=12, gravity≈9.81에 따른 약 2.446초로, 원본 점프와 duration이 다르다. 기존 Jump PNG에서 상승 중 긴 시간 같은 팔·다리 포즈가 반복된다.
새 클립은 crouch/loading→extension→takeoff로 운동량이 연결돼야 한다. 독립 full jump의 authored trajectory와 physics용 in-place phase를 구분해 저장한다. 캐릭터 뿌리 Y를 두 번 올리지 않는다. 2.45초 gameplay 비행에 맞춘다고 한 포즈를 1초 넘게 얼리지 않는다.

AirRise
기존은 source frame 16.8~17.8의 1-frame 폭 looping clip다. 사실상 정지 pose를 긴 상승 구간에 사용한다. 팔이 떠 있고 다리가 고정돼 보이는 직접 원인이다.
새 asset에는 별도 짧은 상승 progression이나 호흡 정도의 변화가 있는 aerial hold를 만들고, takeoff와 apex 사이의 발/골반/팔 움직임이 이어지게 한다. 중력 값에 맞추기 위해 clip 전체를 무한 반복하지 않는다.

AirApex
기존 source 약 25.2~30.8의 5.6-frame 폭(.187초) loop다. 짧은 jump 중간구간의 pose를 반복하여 원래 용도보다 긴 hold에 사용한다.
새 apex는 상승의 뻗음에서 낙하의 접힘으로 지나가는 연결 pose여야 한다. feet/head가 한 번에 바뀌지 않게 velocity-continuous 출입구를 갖춘다. cycle seam와 authored bob을 따로 검수한다.

AirFall
기존 source 36.4~37.4의 1-frame 폭 loop다. PNG 후반부에서 다리가 접힌 모양을 오래 유지하며, 착지 준비와 landing compression 사이의 연결이 없다.
새 fall은 knees/feet의 landing preparation을 살리고, 짧은 fall/long fall에 재사용 가능한 안정 pose와 recovery 동작을 구분한다. 새 Sword_Aerial_Plunge와 혼용하지 않는다.

Land
현행 .433초 source를 .1초에 압축해 pose가 약 2개 GIF frame으로 지나간다. 캡처 #5→#6에서 visual offset이 약 15cm 바뀌어 landing compression이 아니라 캐릭터 높이 pop으로 읽힌다.
새 Land는 foot contact→knee/hip compression→settle/recovery를 실제로 완결한다. full Jump와 별도 Land의 입구를 동일 pose로 맞춘다. 지지 발바닥은 유지하고 힙이 압축되도록 만든다. 소스 보정 단계에서 해결하며 기존 runtime을 바꾸지 않는다.

Dash / Dash_Forward
기존 Dash.anim은 .033초 두 key의 거의 동일 pose이며 .18초 동안 정지 자세를 X 방향으로 미는 구조다. runtime은 source 방향 불일치에 ±40도 visual yaw도 덧붙인다. PNG #4/#6이 같은 낮은 pose여서 anticipation/recovery와 팔/다리 follow-through가 없다.
새 Dash는 준비/몸의 기울임/밀어내기/다리 회수와 착지·복귀를 포함한다. 이동량이나 무적시간을 새 clip에서 gameplay로 구현하지 않는다. sideview heading을 asset에서 맞추고 별도 ±40도 사후 회전 없이 평가한다.

Hit / Hit_Reaction
기존 긴 .933초 reaction을 .3초에 압축하고 Dash와 같은 ±40도 추가 yaw를 쓴다. 몸이 뒤로 젖는 반응은 보이지만 중심·발 지지·복귀가 별도 조립처럼 보인다.
새 Hit는 짧은 impact pose, torso recoil, head lag, 빠른 recover로 구성하고, 큰 물리 root translation은 넣지 않는다. 발 접지를 그대로 둔 작은 recoil와 공중 recoil 용도를 구분한다. 의도한 impact 가속은 비의도적인 one-frame spike와 구분해 판정한다.

Drink / Potion_Drink
현재 source .20~.73을 1.35초로 압축하며, 병 mount는 특정 contact pose에 맞춰 고정 조정됐다. 한 시점에서 입구가 입에 맞아도 올리는 구간·마시는 hold·내리는 구간 전체가 맞는다는 뜻은 아니다. PNG #8~#17에 두 손목/병/머리의 관계가 포즈마다 달라진다.

6. 손 메시의 한계와 새 독립 보정
기존 Grip_R/Grip_L은 hand-weight가 거의 1인 distal finger만 110도 굽히고 엄지·손바닥은 그대로 둔다. 이는 무기 옆의 손가락 직선을 완화하는 용도였으나, 자연스럽게 쥔 주먹은 아니다. 끝마디가 손바닥으로 접혀 오지 않고 엄지가 벌어진 채 남으면 claw/집게 모양이 된다. runtime의 0/100 즉시 shape 전환도 close-up에서 튄다.
새 MotionPolishHandBuilder는 별도 mesh clone에 75/100 두 morph frame을 작성한다. 100은 MCP/PIP/DIP 세 구간의 215도 누적 flexion과 thumb opposition을, 75는 별도 165도 weapon grip 형태를 사용한다. 원본 vertex/normal/tangent/UV/index/bindpose/skin weights는 보존한다. 이 작업은 새 손가락 리그를 추가하는 것이 아니다.
합격은 수치만으로 결정하지 않는다. 주먹의 front/side/three-quarter에서 엄지가 index/middle의 접힌 부분 위에 오고, 손가락 끝이 삐져나온 claw/빈 고리처럼 보이지 않아야 한다. 손목·커프 seam가 벌어지지 않아야 한다. 75에서는 검·staff 손잡이에 지나치게 파고들거나 떠 있지 않아야 한다. 새 review prefab의 default 100은 root builder가 적용하며 기존 인게임 renderer는 건드리지 않는다.

7. 신규 Sword_Horizontal_Slash 기술 조건
- 같은 유효 Humanoid Avatar/24-bone skeleton, 영어 clip 이름. 샘플은 ±X 진행, 약 7도 이내 yaw/pitch의 실제 sideview에서 모두 검수.
- 지지발·전방 무릎·힙 체중 이동을 가진 단일 베기. 손/무기는 canonical near hand에 두고 반대 손은 guard/balance를 담당.
- blade의 active sweep는 허리~가슴 높이의 대체로 수평 XZ arc여야 한다. 큰 overhead loop, 바닥에서 위로 퍼올리는 scooping arc, 두 번째 타격은 제외.
- wind-up→active sweep→follow-through→balanced recover가 한 clip에 포함된다. 완결된 추천 authoring 길이 약 .40~.55초; 더 빠른 용도가 필요하면 phase를 보존한 별도 variant로 검수한다. 이는 gameplay attack duration 변경 요청이 아니다.
- root XZ/yaw travel은 asset의 pose와 분리하여 설명한다. torso의 자연 counter-rotation을 제거하지 않는다. 검날은 손잡이/손목에서 갑자기 180도 뒤집히지 않고, 관절 quaternion 최단경로가 프레임 사이에서 바뀌지 않아야 한다.
- contact candidate는 실제 blade edge/tip의 torso-height sweep와 hand extension을 함께 보고 정한다. maximum speed 한 점이나 옛 .78을 새 asset에 무조건 적용하지 않는다.
- 검 grip는 새 75 morph를 기준으로 하고, 손목/칼날/팔꿈치가 head/torso 안으로 관통하지 않게 한다.

8. 신규 Sword_Aerial_Plunge 기술 조건
- 기존 JumpFull/횡베기 재생을 대체 명칭으로 쓰지 않는 별도 aerial vertical plunge.
- 공중 준비: 무릎/힙은 compact, torso는 진행 방향으로 안정, 손은 handle을 지지하고 sword tip은 명확히 world -Y를 향한다. 머리/검의 실루엣을 분리한다.
- 낙하 hold: 검날이 수직 아래로 향하는 방향과 손-손잡이 관계를 유지한다. 장시간 정지 포즈를 그대로 늘이기보다 짧은 안정 hold/loop를 따로 둘 수 있다. 양발이 동시에 지면에 접지된 자세로 만들지 않는다.
- impact/recovery: contact 직전의 pose→다리/힙 압축→검 회수→균형 회복의 흐름을 작성한다. 실제 plunge 이동/충돌/피해/중력 변경은 구현하지 않는다.
- root의 authored Y 낙하와 향후 physics root Y를 중복 적용하지 않도록 trajectory/phase metadata를 남긴다. 샘플 preview의 이동은 시각화임을 명시한다.
- 가능하면 Sword_Aerial_Plunge_Anticipation / Sword_Aerial_Plunge_Loop / Sword_Aerial_Plunge_Land 형태의 phase 보조 자산을 두고, main clip도 전체 흐름을 이해할 수 있게 유지한다. phase 분리만으로 실제 gameplay state machine이 구현됐다고 보지 않는다.

9. 새 v004 후보의 측정/합격 기준
1) 모든 clip의 nominal duration/source range/frame rate/loop flag/root extraction/Avatar를 manifest에 기록한다. raw source 복제본을 보존한다.
2) 60 또는 120 Hz로 root/hips/head/hands/feet/toes 회전 및 위치를 샘플링한다. rotation은 quaternion sign 연속성을 먼저 맞추고 shortest-angle velocity를 구한다.
3) loops는 정확한 한 주기에서 support foot/hand/head의 위치와 경계 속도를 측정한다. 반복된 끝 프레임을 추가해서 pause를 만들지 않는다. phase가 다르면 최적 endpoint를 찾아 자른 뒤 작은 seam blend를 적용하며 전체 주기를 무작정 저역통과하지 않는다.
4) world 이동/몸통 bob를 분리하고, support 발의 world-space drift·sole height·toe roll을 확인한다. Run의 flight나 aerial pose를 floor snap으로 지우지 않는다.
5) acceleration/jerk는 원시 max 하나 대신 median/p95/p99 및 spike가 난 시간대를 보고한다. Punch/Slash/Hit의 의도한 impact 구간과 loop seam/무기 뒤집힘/단일 프레임 오류를 구분한다.
6) finite action은 entry/exit의 pose/velocity를 canonical Idle 또는 해당 phase와 비교한다. recovery가 부족한 asset은 trim만 바꿔 합격시키지 않는다.
7) contact/grip/socket/bottle alignment를 실제 CPU-baked mesh로 front/side와 좌우 방향에서 확인한다. bone만 맞아도 큰 손/머리 mesh가 관통할 수 있다.
8) 순수 원형 preview와 필요한 최소의 baked correction preview를 구분하고, 기존 runtime global grounding을 몰래 적용해 결과를 좋아 보이게 하지 않는다.
9) 새 review prefab/preview controller/샘플 GIF에만 적용한다. 기존 MainScene/Player/controller/runtime/gameplay는 작업 전후 별도로 불변 확인한다.

10. 도구 현황과 효율
확인 시점에 PATH 및 C:/Program Files/Blender Foundation, C:/Program Files, 사용자 Local Programs에서 Blender 실행파일을 찾지 못했다. Python 환경에 bpy 모듈도 없다. 설치가 전혀 없다고 단정하는 광범위 디스크 검색은 하지 않았다.
Python 3.13, numpy, Pillow, PyYAML은 사용 가능하다. scipy/trimesh는 없다. ffmpeg는 PATH에서 찾지 못했다. Unity 6000.3.21f1 프로젝트와 Unity CLI, humanoid import/editor authoring 및 CPU mesh snapshot 도구는 이미 사용 가능하다. Meshy motion tools는 연결돼 있으나 이 감사에서는 실행/과금하지 않았다.
따라서 별도 Blender 설치를 전제로 막히기보다, 현재 Unity에서 source-copy import→Humanoid sampling→독립 clip 정리/pose 보정→샘플 prefab/GIF 검수의 반복이 가능하다. 재생속도와 retargeting 설정만 조절해 원본 부족함을 감추는 반복 대신, 먼저 각 모션의 phase/발 지지/그립 품질을 판정한 뒤 필요한 범위만 수정한다.
