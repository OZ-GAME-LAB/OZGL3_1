치비 자급형 SourceGait 전환 후 Walk/Run 곡선 차이 분석
2026-10-22

기준과 방법
git HEAD의 기존 v007 Walk_Fists.anim / Run_Fists.anim을 읽었다. 두 blob의 SHA256이 cleanup-original-targeted-baseline.json에 보존된 실제 기준 SHA와 정확히 일치함을 먼저 확인했다. checkout/복구/클립 편집/기준 갱신/Unity 실행은 하지 않았다. 현재 YAML과 모든 직렬화 필드를 비교하고, 키의 quaternion은 각각 정규화하여 같은 회전의 부호 차이를 제외한 각도를 계산했다.

확인 결과
- 기록된 비무기 16개 클립 중 다른 14개는 기준 SHA가 그대로다. Walk와 Run만 바이트 차이가 있다.
- Walk/Run 모두 binding 구조, 키 개수, 키 시간, static clip 설정은 같다. position 키 값의 차이는 0이다.
- Walk quaternion 키 성분 최대 차이: 1.43e-6. 정규화 후 방향 최대 차이: 약 0.000215002도. 위치: RightLeg, t=.13333334초.
- Run quaternion 키 성분 최대 차이: 1.73e-6. 정규화 후 방향 최대 차이: 약 0.000262352도. 위치: LeftLeg, t=.33333334초.
- quaternion tangent도 다르다. inSlope 성분 최대 차이는 Walk 약6.437e-5, Run 약3.4e-5이다. Editor Euler 표현의 기울기 차이는 더 크게 표시될 수 있으므로 quaternion 각도와 같은 값으로 비교하지 않는다.
- 상세 수치/최대 차이 위치/원본·현재 SHA는 cleanup-gait-curve-comparison.json에 있다.

Animator 가설의 확인 범위
HEAD의 기존 v005 소스 prefab에는 Animator가 있었고, avatar와 controller는 fileID0이었다. applyRootMotion=0, cullingMode=0(AlwaysAnimate), updateMode=0이었다. 기존 SourceBank는 샘플링 전에 Animator를 disable했다. 새 보존 Skeleton은 컴포넌트 없이 Transform만 있다.
Animator 유무가 초기화/샘플링 경로에 영향을 줄 수 있다는 가설은 있으나, 원인으로 입증한 것은 아니다. Unity6.3 공식 SampleAnimation 문서와 공개 C# binding은 이 경우의 quaternion 정규화 차이를 명세하지 않는다. 이 분석을 위해 Animator나 샘플링 코드를 바꾸지 않았다.
https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AnimationClip.SampleAnimation.html
https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/Animation/ScriptBindings/AnimationClip.bindings.cs

판정 한계
이 결과는 실제 곡선 내용의 차이가 작다는 수치 기록이다. SHA 차이를 무시하거나 바이트가 동일하다고 표시하지 않는다. tangent가 포함된 실제 보간 결과, 스킨, 발 접지와 전체 동작의 보존은 최종 Unity 캡처의 647개 metadata 및62개 이미지 표본으로 따로 검사해야 한다. 기준을 덮어써서 이 차이를 숨기지 않았다.
