# Stage 01 · 서울 균열 지구

2026-11-18. 실제 실행 대상은 MainScene의 StageManager 첫 항목인 `Assets/2.Prefab/CoreSystem/stage.prefab`이다. 두 번째 스테이지와 별도 Tutorial_Block은 이번 수직·아트 개편의 대상이 아니다. 현재 지형은 수작업 고정 골격이며, 기존 적 선택·스폰·보급 시스템을 사용한다.

## 동선과 전투

경계 X=-12…116, 시작 (-6, 0.05), 보스 포탈 (104, 0). 시작에서 보스까지 수평 이동량은 110m다. 전투 평면은 Z=0이며 지면 아래에는 끊김 없는 단일 충돌면을 둔다.

| 구간 | 실제 범위 / 포탈 | 보행 높이 | 목적 |
| --- | --- | --- | --- |
| 진입 | -12…3 | 0 | 첫 적이 없는 안전한 준비 공간 |
| 시장 | 3…26 / (14,0) | 0 | 근접 적 3마리, 0.65초 간격 |
| 시장 차양 | 26.4…32.8 | 2.25 | 첫 상승의 중간 착지와 지지된 건물 |
| 선택 전망대 | 29…32.2 | 5 | 회복/공격 중 한 가지 보급, 곧바로 옥상으로 연결 |
| 카페 옥상 | 34…58.5 / (45,4.5) | 4.5 | 근접 2 + 원거리 2, 0.55초 간격 |
| 설비 연결교 | 59.2…64.5 | 6.5 | 다음 상승을 읽게 하는 안전한 착지, 회복 보급 확정 |
| 하늘 정원 | 66…88.5 / (76,8.5) | 8.5 | 근접/원거리/돌진 각 2, 0.5초 간격 |
| 하강 테라스 | 88.8…93.5 | 4.5 | 지면의 착지점을 보여 주는 중간 하강 |
| 보스 광장 | 94…116 / (104,0) | 0 | 회복 보급, 넓은 보스 전투 공간, 2초 소환 예고 |

카페의 X=39…42/Y=6.9, 정원의 X=80…83/Y=10.9에는 선택 전투 발판을 둔다. 회피·재진입·공중 공격을 위한 발판이며 필수 적은 각각 하나의 연속된 주 바닥 위에 소환한다. 현재 적 AI가 층간 이동을 하지 못하는 점을 고려한 배치다.

각 일반 포탈은 수평 10m, 수직 1.5m 안에서 소환을 시작한다. 위층 전투가 아래 거리에서 시작되지 않는다. 소환 자체의 대기는 약 1.3/1.65/2.5초다. 이는 전투 완료 시간이 아니다. X=26/58/88의 시각적 봉인은 연결된 전투 완료 시 충돌과 표시가 함께 사라진다. 봉인 높이는 28m로 최고 선택 발판의 최대 점프로도 넘지 못한다.

## 이동과 복귀

- 필수 상승은 높이 차 2…2.25m, 수평 빈틈 0.7…1.5m다. 기존 점프만으로 통과하며 공중 대시를 요구하지 않는다.
- 낮은 옥상 복귀 사다리는 X=33.5, 출구 (34.5,4.55). 높은 옥상 사다리는 X=65.5, 출구 (66.5,8.55)다.
- 사다리 축은 솔리드 덱 밖으로 빼서 머리가 덱 아래에 막히지 않는다. 출구와 주요 착지점에는 소품 충돌을 두지 않는다.
- 지면 전체가 연결되어 낙하 후 복귀할 수 있다. 구덩이나 낙하 즉사는 없다.
- 중간 발판과 선택 전투 발판은 기존 OneWayPlatform을 사용한다. 위로 통과, 착지, S+Space 하강을 실제 입력으로 확인했다.
- 카메라 직렬화 값은 크기 7, 기준 높이 3.5, 피치 6.5도다. 최고 선택 발판의 점프 정점 발 높이 약 18.1m에서도 머리가 화면에 들어오는 것을 확인했다.

## 환경과 시각적 위계

전경은 벽돌색·크림색·청록색과 짙은 구조 경계, 식생은 녹색으로 구성한다. 보행 상판은 밝고, 앞 모서리는 금빛 띠로 읽힌다. 포탈에는 독립된 입체 아치, 어두운 내부 깊이, 청록/보라색 소용돌이와 절제된 입자 효과를 사용한다. 기존 상태 색 변경은 작은 StatusGem에만 적용한다.

옥상은 벽·창·기초·처마가 지면까지 이어진 건물 위에 놓인다. 원경의 바닥은 연속된 도시 기단 안으로 숨기고, 지면이 원경 앞을 자르지 않게 깊이를 조정했다. 하늘에는 월드 높이 그라데이션과 소수의 입체 구름을 둔다. 먼 건물은 낮은 대비로, 실제 통행면과 상호작용 요소는 높은 대비로 분리한다.

가로등·나무·벤치·쓰레기통은 거리의 작은 묶음으로, 옥상 설비·물탱크·화단은 난간 뒤로 배치한다. 환경 장식의 충돌은 비활성화하고 전투 평면과 착지 공간을 비워 둔다. 창·상판·기초의 중첩면, 초기 셰이더 렌더 오류, 구형 포탈 메시 중복을 검수하면서 수정했다.

## 제작과 검증

이번 개편은 프리팹·지도·재질·메시·셰이더·Editor 제작/QA 도구를 수정했다. 요청 시점의 런타임 C#은 보존했다. 보스 포탈이 공격을 받지 못하던 문제는 **이 스테이지 인스턴스의 충돌 레이어**를 기존 무기 대상 레이어에 맞추어 수정했으며, 공격 코드는 바꾸지 않았다.

Editor 메뉴 `OZ > Level Design`:

- `Rebuild Stage 01`: 저장된 제작 기준으로 스테이지와 지도를 재생성한다.
- `Validate Stage 01` / `Validate Vertical Stage 01 Assets`: 정적 에셋·지지면·몸통 공간·스폰·사다리·포탈 타격 마스크를 검사한다.
- `Rebuild Validate And Play`: 재생성·정적 검수 후 실제 타이틀부터 플레이 검증을 시작한다.
- `Start Manual Vertical Play QA`: 정상 Input System 장치 이벤트로 조작하고 실제 HUD 화면·상태를 기록한다. 캐릭터 이동·체력·피해·진행 상태를 직접 변경하지 않는다.

검증 출력은 `OZ_STAGE_QA_DIR`, 플레이 명령과 기록은 프로젝트 밖의 `OZ_STAGE_CONTROL_DIR`에 저장한다. 이전 평지용 검증 진입점도 현재 수직 QA로 연결했다. 직접 피해를 주거나 순간 이동하는 과거 검증 루틴은 제거했다.

정적 검수는 지지면 745곳, 몸통 공간 762곳, 일반/보스 스폰 14곳을 확인한다. 에디터 개관 렌더와 실제 Play Mode 화면은 명시적으로 구분한다. 상세 실측·테스트 조건·미해결 시스템 항목은 [QA 기록](Stage01_Vertical_QA.md), 9개 1차 자료와 적용 근거는 [조사 문서](Stage01_ArtLevel_Research.md)에 정리한다.
